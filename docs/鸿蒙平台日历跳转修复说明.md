# 鸿蒙平台日历跳转功能修复说明

## 问题描述

在鸿蒙 PC 平台上，点击日历按钮无法正常跳转到日历窗口，但在 macOS 平台上可以正常工作。

## 问题原因

经过分析，发现问题的根本原因是：

1. **IPC 通信方式不兼容**：原代码使用 `ipcRenderer.send()` 进行单向通信，在鸿蒙平台上可能存在兼容性问题。

2. **异步处理缺失**：原代码没有正确处理异步结果和错误情况。

3. **调试信息不足**：缺少足够的日志信息来排查鸿蒙平台特有的问题。

## 解决方案

### 1. 修改 IPC 通信方式

**修改前：**
```javascript
// 渲染进程
function openCalendar() {
    ipcRenderer.send('open-calendar');
}

// 主进程
ipcMain.on('open-calendar', () => {
    createCalendarWindow();
});
```

**修改后：**
```javascript
// 渲染进程
function openCalendar() {
    console.log('点击日历按钮，准备打开日历窗口');
    
    ipcRenderer.invoke('open-calendar')
        .then(result => {
            console.log('日历窗口打开结果:', result);
            if (result && result.success) {
                console.log('日历窗口成功打开');
            } else {
                console.warn('日历窗口打开返回异常结果:', result);
            }
        })
        .catch(error => {
            console.error('打开日历窗口失败:', error);
            alert('打开日历窗口失败: ' + error.message);
        });
}

// 主进程
ipcMain.handle('open-calendar', async () => {
    createCalendarWindow();
    return { success: true };
});
```

### 2. 关键改进点

#### a) 使用 `ipcRenderer.invoke()` 替代 `ipcRenderer.send()`

- **invoke()**: 返回 Promise，支持异步处理和结果返回
- **send()**: 单向通信，无返回值，兼容性较差

#### b) 使用 `ipcMain.handle()` 替代 `ipcMain.on()`

- **handle()**: 处理 invoke 调用，支持异步和返回值
- **on()**: 监听 send 事件，无返回值

#### c) 添加完善的错误处理

```javascript
.catch(error => {
    console.error('打开日历窗口失败:', error);
    alert('打开日历窗口失败: ' + error.message);
});
```

#### d) 添加调试日志

```javascript
console.log('点击日历按钮，准备打开日历窗口');
console.log('日历窗口打开结果:', result);
console.log('日历窗口成功打开');
```

### 4. 技术细节

#### IPC 通信对比

| 特性 | send/on | invoke/handle |
|------|---------|---------------|
| 通信方式 | 单向 | 双向（请求-响应） |
| 返回值 | 无 | 有（Promise） |
| 错误处理 | 需手动实现 | 内置 Promise 错误处理 |
| 异步支持 | 有限 | 完整支持 |
| 鸿蒙兼容性 | 可能有问题 | 更好 |

#### 为什么鸿蒙平台需要 invoke/handle？

1. **异步架构**：鸿蒙平台的 Electron 实现可能更严格地要求异步处理
2. **错误处理**：invoke/handle 提供了更好的错误处理机制
3. **结果确认**：可以确认操作是否成功执行
4. **调试友好**：更容易追踪问题

### 6. 其他建议

#### a) 统一使用 invoke/handle

建议项目中所有的 IPC 通信都使用 `invoke/handle` 模式，以提高跨平台兼容性：

```javascript
// ❌ 不推荐
ipcRenderer.send('event-name');
ipcMain.on('event-name', handler);

// ✅ 推荐
ipcRenderer.invoke('event-name');
ipcMain.handle('event-name', handler);
```

#### b) 添加平台检测

可以在代码中添加平台检测，针对不同平台使用不同的策略：

```javascript
const isHarmonyOS = process.platform === 'harmony';

function openCalendar() {
    if (isHarmonyOS) {
        // 鸿蒙平台特殊处理
        ipcRenderer.invoke('open-calendar');
    } else {
        // 其他平台
        ipcRenderer.send('open-calendar');
    }
}
```

#### c) 增强日志系统

建议实现一个统一的日志系统，方便调试和问题排查：

```javascript
function log(message, level = 'info') {
    const timestamp = new Date().toISOString();
    const platform = process.platform;
    console.log(`[${timestamp}] [${platform}] [${level}] ${message}`);
}

// 使用
log('点击日历按钮');
log('日历窗口打开成功', 'success');
log('打开日历窗口失败: ' + error.message, 'error');
```
